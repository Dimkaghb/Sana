# KinetiqSDK

Import the SDK, sensor-permission request, React lifecycle hook, or contract types through `frontend/src/sdk/index.ts`. Call `requestSensorAccess()` in the initiating user gesture, then use `useKinetiq(accountId, enabled, onDemoCommand, access === "allowed")`. For a headless integration, construct `new KinetiqSDK({ accountId, collectMotion: access === "allowed" })`, call `start(onDemoCommand)`, and always call `stop()` on disposal.

Mark transfer controls with `data-kinetiq-field`. Custom keypad buttons set `data-key-group="digit"` or `"backspace"` and the slider sets `data-kinetiq-field="slider"`. The collector records native pointer provenance and geometry, paired key timings, and active slider points. Text and key values are outside the collector’s input. After granted access, motion uses trusted browser sensor events with linear acceleration in m/s² and orientation in degrees. Each motion record pairs fresh acceleration with the latest complete orientation actually observed in that visible session. Browsers may publish orientation only when it changes. A visibility or account transition clears this held angle, and an incomplete browser orientation event invalidates it. Contract A’s measured frequency requires at least two complete observations.

`submit({ amount_kzt, is_new_recipient })` waits for the post-tap window, freezes a bounded session snapshot, closes collection and command delivery, and returns Contract D. Concurrent and retried calls use the same payload. The snapshot retains at most 20 seconds and 4,096 motion records. A new transfer or account gets a new SDK instance.

`saveCalibrationWithConsent()` is available following submission and sends the frozen payload to the explicitly enabled local calibration endpoint. The mobile view calls it only for a transfer on which the participant selected the consent checkbox.
